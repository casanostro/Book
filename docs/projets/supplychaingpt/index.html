CASE 04 Open source Lecture seule

Du français au SQL, avec garde-fous

DomaineIA appliquée, produit
RôleConception, développement
StackClaude API, SQLite, Streamlit
StatutDémonstrateur public

Un assistant qui transforme une question métier en requête validée, l'exécute sur une base réaliste et restitue le résultat, le SQL généré et une visualisation. Ce n'est pas un chatbot. C'est un produit, avec ses garde-fous.

Pipeline produit

De la question à la visualisation, sans boîte noire

01 · Entrée

Une question, en français

« Quels fournisseurs ont le plus de ruptures ce mois ? » L'utilisateur métier n'écrit pas de SQL. Le contexte de schéma (6 tables, exemples de requêtes) est injecté dans le prompt.

02 · Génération

Le LLM propose, il ne dispose pas

Claude API génère une requête SQL candidate à partir de la question et du schéma. Rien n'est exécuté à ce stade : le SQL passe d'abord un contrôle.

03 · Validation

La validation est un nœud, pas une note

Un validateur n'accepte que des SELECT : pas d'écriture, pas de DDL, pas d'appels multiples. Une requête rejetée repart en régénération avec le motif du refus.

Défense en profondeur : même si une écriture passait la validation, la connexion est ouverte en lecture seule. Le pire scénario possible est une requête qui échoue, jamais une donnée modifiée.

04 · Exécution

Un périmètre borné

Exécution sur une base de démonstration SQLite réaliste : 6 tables, 90 jours de commandes et de positions de stock. Connexion en lecture seule, timeout, assez de volume pour que les jointures soient non triviales.

05 · Restitution

Le SQL est toujours montré

Chaque réponse affiche la requête à côté du résultat et d'une visualisation. L'utilisateur métier peut faire vérifier le SQL, l'analyste peut auditer ce que le modèle a demandé à la base. Pas de boîte noire entre la question et le chiffre.

Le flux, garde-fous compris

entrée traitement garde-fou sortie
Un profil qui sait « parler d'IA » décrit un chatbot. Un profil qui sait travailler avec des systèmes réels pose d'abord la question de la validation et de l'accès aux données. Leçon du dossier

Code ouvert : github.com/casanostro/supply-chain-gpt. Suite de tests de régression sur 10 questions métier de référence, rejouée à chaque évolution du prompt ou du schéma : si une réponse change de sens, le pipeline ne part pas.

Deux lectures d'une même donnée : le produit n'est pas la techno, c'est l'audience.
