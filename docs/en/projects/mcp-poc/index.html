PROJECT [06]

MCP POC — querying the data warehouse in natural language

An MCP (Model Context Protocol) server puts the LLM in front of Snowflake with typed tools and a controlled scope. The warehouse documentation reference — built by hand — becomes the context that makes the model reliable on a real warehouse.

WHAT MAKES THE POC RELIABLE

Yesterday's documentation is today's guardrail

principle_01

The reference as context

The LLM doesn't guess the schema: it receives the technical reference built during the data warehouse documentation — 24 mapped schemas, the lineage of ~65 views, the known pitfalls. That structured context is the difference between a demo and a tool.

principle_02

Typed tools, not raw access

The MCP server doesn't expose a SQL connection: it exposes three narrow tools — list schemas, describe a view, run a SELECT query. The model explores the warehouse in observable steps, never blindly.

principle_03

Read-only, closed scope

The Snowflake role used by the server is read-only and limited to the documented schemas. Even an adversarial prompt can neither write nor leave the scope: the constraint lives in the infrastructure, not in the prompt.

principle_04

Sourced answers

Every answer cites the views it queried and attaches the executed SQL. A business team can check the source, a data engineer can replay the query: trust is built on auditability, not on the model's authority.
