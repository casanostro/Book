NODE : PROJET [01]

SupplyChainGPT — du français au SQL, avec garde-fous

Un assistant text-to-SQL qui transforme une question métier en requête validée, l'exécute sur une base réaliste et restitue le résultat, le SQL généré et une visualisation automatique. Chaque étape sensible est un nœud explicite du pipeline.

NODE : LES GARDE-FOUS

Pourquoi la validation est un nœud, pas une note de bas de page

garde-fou_01

Validation SQL avant exécution

Le SQL généré par le LLM n'est jamais exécuté directement : il passe par un validateur qui n'accepte que des requêtes SELECT — pas d'écriture, pas de DDL, pas d'appels multiples. Une requête rejetée repart en régénération avec le motif du refus.

garde-fou_02

Connexion en lecture seule

Défense en profondeur : même si une requête d'écriture passait la validation, la connexion SQLite est ouverte en mode read-only. Le pire scénario possible est une requête qui échoue, jamais une donnée modifiée.

garde-fou_03

Le SQL est toujours affiché

Chaque réponse montre la requête générée à côté du résultat : l'utilisateur métier peut faire vérifier le SQL, et l'analyste peut auditer ce que le modèle a réellement demandé à la base. Pas de boîte noire entre la question et le chiffre.

garde-fou_04

Tests de régression métier

Une suite de 10 questions métier de référence (ruptures, taux de service, stocks) est rejouée à chaque évolution du prompt ou du schéma : si une réponse change de sens, le pipeline ne part pas.
