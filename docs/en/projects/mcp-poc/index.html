Querying the warehouse in plain language

The technical detail of part 2 of CASE 03. An MCP server puts an LLM in front of Snowflake with typed tools and a controlled scope. The hand-built reference becomes the context that makes the model reliable on a real warehouse.

What makes the PoC reliable

Yesterday's documentation is today's guardrail

principle 01

The reference as context

The model does not guess the schema: it receives the reference built while documenting the warehouse, 24 schemas and the lineage of about 65 views. That context is the difference between a demo and a tool.

principle 02

Typed tools, not raw access

The server does not expose a SQL connection: it exposes three narrow tools, list schemas, describe a view, run a SELECT. The model explores in observable steps, never blind.

principle 03

Read-only, bounded scope

Read-only role, controlled schema scope, quotas. The worst possible case is a query that fails, never modified data. Security is not in the model; it is in what you let it do.

principle 04

Self-service, not magic

The answer cites its sources and attaches its SQL. A team can check, an analyst can audit. That is the adoption condition: a tool you can control is a tool people use.
