PROJET [04]

Le datawarehouse documenté de zéro — du reverse-engineering à la source de vérité

La documentation existante mentionnait 4 schémas. L'exploration en a révélé 24, répartis sur 3 bases. Ce projet a reconstruit le lineage réel d'environ 65 vues et produit le référentiel technique qui sert aujourd'hui de contexte au POC MCP.

ARCHITECTURE : EXPLORATION → LINEAGE → RÉFÉRENTIEL

Cartographier ce qui existe, pas ce qui est déclaré

traitement livrable réutilisation IA (projet 06) — pointillés : consommation du référentiel
POURQUOI ÇA COMPTE

La cartographie comme actif, pas comme corvée

constat_01

Le déclaré n'était pas le réel

Quatre schémas documentés, vingt-quatre en production : l'écart n'était pas un détail, c'était le quotidien des équipes — chaque question sur une vue inconnue remontait à la même personne. Le référentiel a cassé cette dépendance aux savoirs individuels.

constat_02

Un référentiel qui sert deux fois

Écrit d'abord pour les humains, le référentiel est devenu le contexte structuré du POC MCP : les 24 schémas et le lineage des vues sont exactement ce dont un LLM a besoin pour interroger l'entrepôt sans halluciner de tables.
