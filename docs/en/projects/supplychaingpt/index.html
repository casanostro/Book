From plain English to SQL, with guardrails

DomainApplied AI, product
RoleDesign, development
StackClaude API, SQLite, Streamlit
StatusPublic demonstrator

An assistant that turns a business question into a validated query, runs it on a realistic database and returns the result, the generated SQL and a visualisation. This is not a chatbot. It is a product, with its guardrails.

Product pipeline

From question to visualisation, no black box

01 · Input

A question, in plain language

"Which suppliers have the most stockouts this month?" The business user writes no SQL. The schema context (6 tables, sample queries) is injected into the prompt.

02 · Generation

The LLM proposes, it does not dispose

Claude API generates a candidate SQL query from the question and schema. Nothing runs at this stage: the SQL first passes a check.

03 · Validation

Validation is a node, not a footnote

A validator accepts only SELECT: no writes, no DDL, no multiple statements. A rejected query goes back for regeneration with the reason for refusal.

Defence in depth: even if a write passed validation, the connection is opened read-only. The worst possible case is a query that fails, never modified data.

04 · Execution

A bounded scope

Execution on a realistic SQLite demo database: 6 tables, 90 days of orders and stock positions. Read-only connection, timeout, enough volume for joins to be non-trivial.

05 · Response

The SQL is always shown

Every response shows the query next to the result and a visualisation. The business user can have the SQL checked, the analyst can audit what the model asked the database. No black box between the question and the number.

Architecture

The flow, guardrails included

inputprocessing guardrailoutput
A profile that can "talk about AI" describes a chatbot. A profile that can work with real systems asks the validation and data-access question first. Lesson from the case

Open source: github.com/casanostro/supply-chain-gpt. A regression suite of 10 reference business questions is replayed on every prompt or schema change: if a response changes meaning, the pipeline does not ship.

Two readings of the same data: the product is not the tech, it is the audience.
