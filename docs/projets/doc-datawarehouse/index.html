CASE 03 Source de vérité Deux parties

Avant l'agent, l'entrepôt

La documentation existante mentionnait 4 schémas. L'exploration en a révélé 24. Avant de construire l'agent, il a fallu comprendre l'entrepôt. Deux projets, une seule histoire.

Le déclaré n'était pas le réel. L'écart n'était pas un détail : c'était le quotidien des équipes, où chaque question sur une vue inconnue remontait à la même personne.

Partie 1 · L'entrepôt

Cartographier ce qui existe, pas ce qui est déclaré

01 · Le déclaré

Une doc qui ne dit pas le réel

Trois bases Snowflake, une documentation qui n'en couvrait qu'une fraction. Impossible de faire évoluer ou déboguer sereinement une chaîne data dont personne n'a la carte complète.

02 · L'exploration

Interroger le système lui-même

Exploration systématique via information_schema et GET_DDL. Le système décrit sa propre structure ; il suffit de savoir lui poser la question. 24 schémas réels, six fois le périmètre documenté.

03 · Le lineage

Reconstruire les dépendances réelles

Parsing du DDL des vues pour reconstituer qui dépend de quoi : environ 65 vues, leurs dépendances réelles, pas celles supposées. La carte devient exploitable.

04 · Le référentiel

Un actif, pas une corvée

Un référentiel technique de 314 lignes, devenu la source de vérité de la chaîne data. Il casse la dépendance aux savoirs individuels : la carte survit à celui qui l'a dessinée.

Écrit d'abord pour les humains, il s'est révélé être exactement ce dont un modèle a besoin pour interroger l'entrepôt sans inventer de tables.

Partie 2 · L'agent

La cartographie d'hier, garde-fou de l'IA d'aujourd'hui

Le prolongement direct : un connecteur MCP entre un LLM et Snowflake. Les équipes posent leurs questions en langage naturel, le modèle explore le schéma, génère la requête et répond avec ses sources. Accès en lecture seule, périmètre de schémas contrôlé.

Le référentiel construit en partie 1 n'est pas un document annexe : c'est le contexte structuré qui empêche le modèle d'halluciner des tables. Les 24 schémas et le lineage des vues sont exactement ce dont un LLM a besoin pour rester fiable sur un entrepôt réel. Du reverse-engineering au self-service, sans jamais donner au modèle plus que la lecture.

Un LLM branché sur un entrepôt qu'on n'a pas cartographié invente des réponses avec aplomb. Le garde-fou n'est pas dans le modèle ; il est dans le contexte qu'on lui donne. Leçon du dossier

La suite logique : le même principe de garde-fous, poussé jusqu'au produit.
