04Method

A project lifecycle in seven steps

I do not start with the technology. I start with the stakes and the stakeholders, then with the data that measures them. An approach in the spirit of the PMBOK: value-driven, tailored to context, predictive or agile as needed.

05Beliefs

Five things I hold to be true

01
Bad data is not a technical detail. A false, reassuring metric costs more than a true, uncomfortable one. A system's silence is often the real bug.
02
Automating a bad process only speeds up the problem. 159 automations does not mean 159 reliable ones. The question is not how many, but which ones hold in production, and what risk each one carries.
03
A deliverable only has value once adopted. A dashboard is designed for a stakeholder before it is designed in charts. The single dashboard "for everyone" is the classic mistake: it serves no one.
04
Documentation is infrastructure. A system only I understand is a project risk, not an achievement. Written once, a good map serves teams and models alike.
05
A useful increment beats a perfect backlog never shipped. Deliver early, measure, adjust. AI follows the same rule: it augments business judgment given a clear scope, guardrails, evaluation, and a human in the loop.
