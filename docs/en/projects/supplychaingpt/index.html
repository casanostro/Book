PROJECT [01]

SupplyChainGPT — from plain language to SQL, with guardrails

A text-to-SQL assistant that turns a business question into a validated query, runs it against a realistic database and returns the result, the generated SQL and an automatic chart. Every sensitive step is an explicit node in the pipeline.

THE GUARDRAILS

Why validation is a node, not a footnote

guardrail_01

SQL validated before execution

SQL generated by the LLM is never executed directly: it goes through a validator that only accepts SELECT statements — no writes, no DDL, no multi-statements. A rejected query is regenerated with the rejection reason.

guardrail_02

Read-only connection

Defence in depth: even if a write query slipped past validation, the SQLite connection is opened read-only. The worst possible outcome is a failed query — never modified data.

guardrail_03

The SQL is always shown

Every answer displays the generated query next to the result: business users can have the SQL checked, and analysts can audit exactly what the model asked the database. No black box between the question and the number.

guardrail_04

Business regression tests

A suite of 10 reference business questions (stockouts, service level, inventory) is replayed on every prompt or schema change: if an answer changes meaning, the pipeline doesn't ship.
