ANNEXE · CASE 03 Lecture seule

Interroger l'entrepôt en langage naturel

Le détail technique de la partie 2 de CASE 03. Un serveur MCP place un LLM face à Snowflake avec des outils typés et un périmètre contrôlé. Le référentiel construit à la main devient le contexte qui rend le modèle fiable sur un entrepôt réel.

Architecture

Trois couches, deux frontières contrôlées

entrée traitement garde-fou sortie
Ce qui rend le POC fiable

La documentation d'hier est le garde-fou d'aujourd'hui

principe 01

Le référentiel comme contexte

Le modèle ne devine pas le schéma : il reçoit le référentiel construit lors de la documentation de l'entrepôt, soit 24 schémas et le lineage d'environ 65 vues. C'est ce contexte qui fait la différence entre une démo et un outil.

principe 02

Des outils typés, pas un accès brut

Le serveur n'expose pas une connexion SQL : il expose trois outils étroits, lister les schémas, décrire une vue, exécuter un SELECT. Le modèle explore par étapes observables, jamais en aveugle.

principe 03

Lecture seule, périmètre borné

Rôle en lecture seule, périmètre de schémas contrôlé, quotas. Le pire scénario possible est une requête qui échoue, jamais une donnée modifiée. La sécurité n'est pas dans le modèle ; elle est dans ce qu'on l'autorise à faire.

principe 04

Du self-service, pas de la magie

La réponse cite ses sources et joint son SQL. Une équipe peut vérifier, un analyste peut auditer. C'est la condition d'adoption : un outil qu'on peut contrôler est un outil qu'on utilise.
